# Migrating the datom type system into `datom-core`

The type model in `datom-lang/src/types.rs` becomes *the* type model for the
platform. The inference-era types in `datom-core` (`InferredType`,
`RecordType`, `RecordField`) are retired, and `.types.datom` files become
real datom source.

## Where things stand

| | |
|---|---|
| `datom-lang/src/types.rs` | `Type`, `TypeDetails`, `Sum`, `Fields`, `CollectionDetails`, `Primitive`, `Collection`. All `pub(crate)`. 12 tests, all `Display`-based. |
| `datom-core/src/schema.rs` | `InferredType`, `RecordType`, `RecordField`, `InferredSchema` + inference from JSON. 17 tests. |
| `datom-core/src/types_format.rs` | Hand-written `table`/`record` grammar, ~1350 lines, 24 tests. |
| `datom-core/src/schema_diff.rs` | Diffs two `InferredType`s. 7 tests. |
| `datom-core/src/introspect.rs` | Writes the types file; reads the previous one back to diff. 8 tests. |
| `datom-core/src/connectivity.rs` | Reads the types file to check the recorded contract. 12 tests. |
| `datom-cli/tests/` | 28 integration tests; `introspect.rs` and `list.rs` call `parse_tables` / `save_tables` directly. |

Two facts shape everything below.

**`Primitive` and `Collection` are lexical, not just semantic.**
`scanner.rs:166-172` turns keywords into them and `parser.rs:69-76` builds
`TYPE_NAME_KINDS` from them. They cannot stay behind in lang, and lang cannot
stop depending on them. So `datom-lang` gains a dependency on `datom-core`.

**That makes `core -> lang` a cycle.** But reading `.types.datom` back needs
the lang parser, and today that read happens inside core
(`introspect.rs:151 recorded_tables`, `connectivity.rs:421 load_stored_tables`).
The resolution: core declares the boundary, lang implements it.

```rust
// datom-core
pub trait TypeReader {
    fn read_types(&self, source: &str) -> std::result::Result<Vec<Type>, String>;
}

// datom-lang  (lang already depends on core, so this impl is legal)
impl datom_core::TypeReader for DatomTypeReader { ... }

// datom-cli  (depends on both) passes it in
introspect_datasource(&root, name, &DatomTypeReader)
```

Writing needs no boundary: rendering is `Display`, which lives with `Type` in
core.

## Decisions taken

**Accept the model loss.** `Integer` and `Float` both become `number`; `Date`
becomes `datetime`; per-field `optional` and declaration order are gone
(`Fields` is a `HashMap`, and `Display` sorts alphabetically, so output stays
deterministic). Consequences to expect: `schema_diff` loses its
became-optional / became-required changes, and `types_format`'s round-trip
tests that assert field order will change meaning.

**`.types.datom` becomes datom source.** `type users(id: number)` instead of
`table users { id: int }`. `types_format.rs` goes away; rendering is `Display`
and parsing is the lang scanner + parser. Existing project files stop parsing
— acceptable, they are regenerated by `datom datasource introspect`.

**`datom-lang` depends on `datom-core` directly**, heavy dep tree and all.
Revisit with a feature gate only if lang's build time becomes annoying.

Two sub-decisions are deferred to Step 1, where they get written down:

- **`Null` / `Unknown` have no home in the new model.** A field only ever seen
  as null, or the element type of an always-empty array, has to become
  something. Recommendation: drop the field and report it in the introspect
  output, rather than inventing a `string` that lies about the data.
- **Every `Type` has a name; unions don't.** `InferredType::Union` is
  positional, but `Sum::InlineVariadic` is reached through
  `Type::inline_variadic(name, ...)`. Recommendation: name a union after the
  field that holds it, the same rule records already use.

## Shape of the work

Steps 2-4 do all their work inside `datom-lang`, where the tests are fast and
the blast radius is one crate. Step 5 is a pure move. Step 7 is the one large
step and it is large because inference, diffing, the file format and both
readers are a single connected component — there is no way to split write from
read without building an adapter that would be deleted a commit later. Steps
2-4 and 6 exist to shrink it.

Every step ends with `cargo test --workspace` green and one commit.

| Step | What | Size |
|---|---|---|
| 1 | Survey and decision record | docs only |
| 2 | Equality and public surface on the lang type model | small |
| 3 | Lowering: AST -> `Vec<Type>` | large |
| 4 | Rendering: `&[Type]` -> datom source, round-trip proven | medium |
| 5 | Move `types.rs` into `datom-core` | mechanical |
| 6 | `InferredType -> Type` conversion, with the losses tested | medium |
| 7 | The flip: inference, diffing, file format, both readers | large |
| 8 | Delete `InferredType` and the bridge | small |
| 9 | Cleanup | small |

# The prompts

Each is self-contained. Run them in order, one per session or one per commit.

## Step 1 — Survey and decision record

```
Read crates/datom-lang/src/types.rs and crates/datom-core/src/{schema.rs,
schema_diff.rs,types_format.rs}, plus the call sites in introspect.rs and
connectivity.rs.

Write docs/type-migration.md recording, for the migration of the lang type
system into datom-core:

1. A mapping table, every InferredType variant -> its Type equivalent, with
   the lossy ones marked: Integer|Float -> Primitive::Number, Date ->
   Primitive::DateTime, RecordField.optional -> dropped, field order ->
   dropped (Fields is a HashMap; Display sorts alphabetically).

2. A decision on InferredType::Null and InferredType::Unknown, which have no
   equivalent. Recommend dropping the field from the record and surfacing it
   in the introspect report rather than substituting a primitive that
   misdescribes the data. State the alternative and why it lost.

3. A decision on naming anonymous unions. Type::inline_variadic requires a
   name but InferredType::Union is positional. Recommend naming the union
   after the field that holds it, matching the rule records already use.
   Say what happens for a union at the top level of a table, where there is
   no enclosing field.

4. The dependency direction: datom-lang gains a dependency on datom-core
   because scanner.rs and parser.rs consume Primitive and Collection as
   keyword payloads. Note that this forbids core -> lang, and that the
   read-back path in introspect.rs:151 and connectivity.rs:421 therefore
   needs a trait in core that lang implements and datom-cli injects.

5. An inventory of every consumer that has to change, file and line.

No code changes. Prose and tables only. Keep it under 150 lines.
```

## Step 2 — Equality and public surface on the lang type model

```
In crates/datom-lang/src/types.rs only.

The type model is about to be compared, constructed and inspected from
outside this module. Prepare it:

- Derive PartialEq and Eq on Type, TypeDetails, Sum and CollectionDetails.
  Primitive and Collection already have them. Note in a comment that Type
  equality is structural and that Fields being a HashMap makes it
  order-insensitive, which is intended.
- Add accessors for CollectionDetails's private `kind` and `generic` fields.
- Keep everything pub(crate) for now; the move to core is a later step.

Add tests for the equality semantics specifically: two Type::single values
built with their fields inserted in different orders compare equal; two
collections differing only in `kind` do not.

cargo test -p lang must pass.
```

## Step 3 — Lowering: AST to `Vec<Type>`

```
In crates/datom-lang, add lowering from the parser AST to the semantic type
model. This is the missing half of types.rs: nothing currently produces a
Type.

Add crates/datom-lang/src/lower.rs with, roughly:

    pub(crate) fn lower(source: &str, program: &Program, diag: &Diagnostics)
        -> Result<Vec<Type>, CompileError>

Requirements:

- Statement::Type(TypeStatement::Single) -> Type::single, Variadic ->
  Type::variadic, InlineVariadic -> Type::inline_variadic.
- TypeName::Concrete resolves a primitive keyword to Type::primitive, and an
  identifier to a previously declared type. TypeName::Generic resolves to
  Type::collection over its lowered element type.
- An identifier naming no declared type is an error reported through
  Diagnostics with the token's range, matching how ParseError does it in
  error.rs. Do not panic.
- A duplicate type name is an error, likewise ranged.
- Statement::Expr is ignored; only type declarations lower.
- Decide and document forward references: either types must be declared
  before use, or resolve in two passes. Pick declaration-order-first, it is
  simpler, and say so in the module doc.

Expose it from lib.rs as a public entry point alongside parse():

    pub fn types(source: &str) -> Result<Vec<Type>, CompileFailure>

scanning + parsing + lowering, with the same CompileFailure-carries-the-
diagnostics behaviour parse() has.

Test against crates/datom-lang/samples/tour.datom: it must lower cleanly and
produce the expected count and names. Add unit tests for the unknown-name and
duplicate-name errors, asserting the rendered diagnostic.
```

## Step 4 — Rendering a set of types as a program

```
In crates/datom-lang. Display on Type prints one declaration and refers to
nested types by name; there is nothing that prints a whole schema as a valid
source file.

Add a renderer:

    pub fn render_types(types: &[Type]) -> String

- One declaration per type, blank-line separated.
- Dependency order: a type is emitted after every type it references, so the
  output re-parses under the declaration-order-first rule from Step 3.
- Nested named types reached through fields are emitted once each, not
  inlined and not duplicated.
- Primitives and collections are never emitted as declarations of their own.

Verify the existing Display output is grammar-exact against the parser, not
just plausible. samples/tour.datom is the reference: single is
`type Tag(label: string)` with no trailing semicolon, variadic is
`type Product { Online(...), InStore(...) }`, inline variadic is
`type Id = string | number;` with one. Fix Display if it diverges.

The test that matters is round-trip. For samples/tour.datom:

    let a = types(source)?;
    let b = types(&render_types(&a))?;
    assert_eq!(a, b);

Add smaller round-trips for nested collections (list<list<number>>),
map<string>, and a variadic whose variant field references another declared
type.
```

## Step 5 — Move the type model into `datom-core`

```
Pure move, no behaviour change.

- git mv crates/datom-lang/src/types.rs crates/datom-core/src/types.rs
- Make Type, TypeDetails, Sum, Fields, CollectionDetails, Primitive and
  Collection pub, with doc comments on each public item (datom-core documents
  its public surface; match the style in schema.rs).
- Register `pub mod types;` in datom-core/src/lib.rs and re-export the names
  alongside the existing schema re-exports. Check for collisions with what
  lib.rs already exports.
- Add `datom-core = { path = "../datom-core" }` to crates/datom-lang/Cargo.toml.
- In datom-lang, replace src/types.rs with a re-export so scanner.rs,
  parser.rs, error.rs and lower.rs keep compiling unchanged:
      pub(crate) use datom_core::types::*;
  Either as a small src/types.rs or as a `use` in lib.rs, whichever reads
  better.
- The 12 type tests move with the file into datom-core.

Verify: cargo test --workspace passes, and `cargo tree -p lang` shows the new
edge. Nothing else in either crate changes.
```

## Step 6 — `InferredType` to `Type` conversion

```
Pure addition to datom-core. This isolates the semantic losses into one
tested function before anything depends on them.

Add to crates/datom-core/src/schema.rs (or a new convert.rs):

    impl From<&InferredType> for Type

following docs/type-migration.md exactly:

- String -> Primitive::String, Boolean -> Primitive::Bool,
  Integer|Float -> Primitive::Number, Date|DateTime -> Primitive::DateTime.
- Record(RecordType) -> Type::single(name, fields), optional discarded.
- Array(inner) -> Type::collection(Collection::List, inner).
- Union(members) -> Type::inline_variadic, named per the Step 1 decision.
- Null and Unknown per the Step 1 decision.

Because a record's name comes from the RecordType but a union's does not, the
conversion needs a name hint threaded through it. Match how schema.rs already
threads name_hint in infer_value.

Test every arm, including: a record whose field is only ever null; nested
records keeping their names; list<list<number>>; a union of two records; and
that Integer and Float converge on the same Type.

No consumer changes yet. Both models coexist after this step.
```

## Step 7 — The flip

```
The large one. Inference, diffing, the file format and both readers are one
connected component and move together.

In datom-core:

1. schema.rs: infer_value, infer_records and infer_response produce Type.
   InferredSchema keeps its name/envelope/record_count fields; only `ty`
   changes. Reuse the Step 6 conversion internally if that keeps the diff
   small, or infer straight into Type if that reads better.

2. schema_diff.rs: diff Type instead of InferredType. The optional-related
   SchemaChange variants have nothing to describe any more; remove them and
   their tests. Sum::Single field maps replace the RecordField vectors.

3. types_format.rs: delete the hand-written grammar. Keep TYPES_FILE_SUFFIX
   and types_path. save_tables renders with lang's render_types. Reading
   moves behind the boundary:

       pub trait TypeReader {
           fn read_types(&self, source: &str)
               -> std::result::Result<Vec<Type>, String>;
       }

4. introspect.rs recorded_tables and connectivity.rs load_stored_tables take
   a &dyn TypeReader. Thread it up through introspect_datasource and
   test_datasource. StoredTypes::Unreadable now carries a lang diagnostic
   string, which is an improvement worth keeping in the message.

In datom-lang: implement datom_core::TypeReader over types() from Step 3.

In datom-cli: pass the lang reader at every call site. Update
tests/introspect.rs and tests/list.rs, which call parse_tables and
save_tables directly and assert on the old grammar; their fixtures become
datom source.

Do not fix anything else you notice along the way. cargo test --workspace
green before committing, and check the CLI end to end: init a project, add a
datasource against a wiremock endpoint, introspect it, and confirm the
written .types.datom parses with `datom parse`.
```

## Step 8 — Delete the old model

```
In datom-core, remove InferredType, RecordType, RecordField, the Step 6
From impl, and any helper that existed only to serve them (check
rename_as_inferred and the primitive_from / type_expr helpers left over from
types_format).

Update the re-export list in lib.rs. Remove the CoreError variants that no
longer have a source: TypesRender and TypesParse were raised by the deleted
grammar — confirm nothing else raises them before deleting.

cargo test --workspace, then cargo clippy --workspace --all-targets. Expect
dead-code warnings to point at anything the deletion orphaned.
```
